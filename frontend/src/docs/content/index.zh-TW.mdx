Orchestrator 是一款用來監督 AI 程式設計 agent 的桌面應用程式。它為每個 worker 提供隔離的工作區，保留可隨時開啟的對話或終端機，並將 Git 工作連結至 PR、CI、審查與合併衝突。

程式碼由 agent 撰寫。Orchestrator 協助您管理專案與 session、追蹤進度、傳送指示、審查變更，以及開啟瀏覽器預覽。

<Callout type="info" title="最快的入門方式">
	下載桌面應用程式、新增儲存庫，再啟動一個小型 session。請先閱讀[安裝](/installation)，再閱讀[快速開始](/quickstart)。
</Callout>

<span id="what-ao-helps-you-do" />
<span id="what-orchestrator-helps-you-do" />
## Orchestrator 能協助您做什麼

- 同時執行多個程式設計 agent，讓各自的檔案、分支與 PR 保持獨立。
- 為每個 session 選擇原生終端機介面或結構化對話介面。
- 從桌面應用程式追蹤活動、CI、審查意見與是否可合併。
- 將後續指示傳送給正確的 worker。
- 執行 reviewer，將要求修改的內容交回 worker。
- 在 session 的對話或終端機旁，預覽其本機應用程式。
- 透過 Automations 排定週期性工作，並透過 Cue 重複使用專案指示或 shell 指令。
- 透過 Connect Mobile，在搭配的行動應用程式中查看進度並回應。

每個 worker 都有明確且便於審查的成果時，最能發揮 Orchestrator 的效益，例如聚焦的錯誤修正、功能、重構、測試、說明文件更新，或審查後的修正。

<span id="the-basic-loop" />
## 基本流程

```text
add project -> start session -> isolated worktree -> pull request -> CI/review -> merge -> cleanup
```

您可以從桌面應用程式或選用的 CLI 建立 session。Orchestrator 會啟動所選 agent 的介面，並結合已儲存的活動與 PR 資料，顯示 session 狀態。

<span id="chat-and-terminal-ui" />
## 對話與終端機介面

每個 session 在同一時間只會使用一個 agent 介面：

| 介面 | 適用情境 |
| --- | --- |
| **對話（Chat）** | 結構化訊息、活動、核准、計畫、用量與對話紀錄。 |
| **終端機介面（Terminal UI）** | harness 原生的互動式終端機體驗。 |

是否支援對話介面，取決於 harness 與已安裝的版本；請參閱[agent 能力目錄](/plugins/agents#chat-versus-terminal-ui)。相容的 session 可以保留原 session 與 worktree，直接切換介面；畫面上會顯示可用的切換方式。

<span id="where-local-data-lives" />
## 本機資料儲存位置

<span id="local-by-design" />

桌面應用程式會在 `127.0.0.1` 執行 Go 背景服務，並透過本機 API 與其通訊。Orchestrator 預設將應用程式資料及 worktree 中繼資料儲存在 `~/.ao`。多數整合會使用電腦上既有的程式設計 agent 及版本控制憑證；Orchestrator 不會隨附外部 agent 或其憑證。Unreal Agent 是 macOS 與 Linux 上內建、僅支援對話介面的配接器。

Connect Mobile 使用獨立、須主動啟用的接聽器，並由連線密碼保護。本機與安全遠端配對方式請參閱 [Connect Mobile](/configuration/remote-access)。

本手冊以 2026 年 10 月 1 日發布的最新穩定版 [v0.13.3](https://github.com/Untrivial-ai/agent-orchestrator/releases/tag/v0.13.3) 為核對基準。`main` 上較新的控制項可能與該版本不同；使用新控制項前，請先查看[變更紀錄](/changelog)及其版本說明。

雲端 session 是獨立服務，須符合帳號存取條件。設定方式請參閱[雲端指南](/guides/cloud)。

<span id="supported-agents" />
## 支援的 agent

Orchestrator 支援 Claude Code、Codex、Cursor、Aider、OpenCode、Droid、Kimi Code 與 GitHub Copilot 等程式設計 agent。各工具對 worker、對話介面及審查角色的支援程度不同；請查看[agent 目錄](/plugins/agents)。雲端服務支援的[供應商種類較少](/guides/cloud#before-you-start)。

GitHub 與 GitLab 提供版本控制狀態觀測與議題匯入。議題匯入須主動啟用，且只會讀取議題追蹤系統；不支援 Linear 與舊版 Node 外掛套件。
